MODEL NOTES

A lab for delivery decisions.

This is a discrete-event simulation, not a forecast. The dashboard and CLI run the same Python / SimPy engine.

  • One store in the centre of a 4 × 4 km street grid. Routes use Manhattan distance.
  • Demand follows Poisson order attempts. A customer can have one outstanding order, so accepted demand can fall below the configured attempt rate.
  • Packing is FIFO, with normally distributed service times: mean 2.25 min, standard deviation 0.4 min, bounded to 1–3.25 min.
  • Dispatch chooses FIFO or shortest trip among ready orders waiting for a rider. No batching. Riders travel at constant speed, spend 0.5 min at handoff, and return before accepting another order.
  • Delivery times and SLA percentages include completed orders. Overdue active orders are reported separately. Utilization includes return trips.
  • The run stops at the chosen duration; open orders remain unfinished. There is no drain period, traffic, inventory, payment, weather, or multi-store routing.
  • Same seed keeps demand attempts and customer selection repeatable. Staffing changes may alter accepted orders because customers wait for completion.

Runs stay in this browser session. A saved baseline is stored on this device. Initial engine loading requires internet access to the pinned Pyodide runtime.
